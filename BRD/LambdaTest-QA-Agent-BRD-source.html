1. Executive summary

Website testing today takes a lot of manual effort: writing test cases, running them on many phones and browsers, collecting screenshots and writing a report. The LambdaTest QA Agent automates this work. A tester gives it a short brief (the website, the requirements document, the test types and the devices). The agent writes the test cases and a test plan, waits for a person to approve it, runs the tests on LambdaTest's cloud of real devices and browsers, and produces a test report that ends with a clear Go / No-Go release decision.

In one line: the agent does the repetitive QA work. People keep the decisions: they approve the plan before anything runs and decide on release from the report.

2. Business problem

  • Manual effort: writing test cases, executing them and preparing reports by hand takes significant tester time for every release.
  • Device coverage: buying and maintaining real iPhones, Android phones and desktop browsers is costly; teams often test on only one or two.
  • Inconsistent output: test cases and reports vary from tester to tester, which makes them harder to review and compare.
  • Unclear release decisions: managers need a simple answer (ship or not) backed by evidence, not a long list of raw results.

4. Scope

4.1 In scope

  • Website (web and mobile web) testing on LambdaTest / TestMu AI: real iOS and Android devices and desktop browsers.
  • Ten test types: smoke, sanity, functional, UI (vs Figma or design images), regression, responsive / cross-browser, accessibility (WCAG 2.2 AA), performance (Lighthouse / Core Web Vitals), SEO and unit.
  • Writing test cases (Markdown and CSV), a test plan, and a test report (Markdown, Excel, PDF) with evidence such as screenshots and session links.
  • A mandatory human approval step between planning and execution.

4.2 Out of scope

  • Load, stress and security / penetration testing.
  • Native mobile apps (App Store / Play Store builds).
  • Submitting real forms, payments or captchas on production unless explicitly approved.
  • Automatic bug filing in an external tracker (bugs are listed in the report).

8. Functional requirements

Priority: MUST required for go-live · SHOULD important · COULD nice to have.

IDRequirementPriority
FR-01The agent shall collect a brief: website URL, BRD/PRD (optional), test types, pages/flows, devices and LambdaTest credentials.MUST
FR-02If no devices are given, the agent shall default to the latest iOS and Android phones.MUST
FR-03The agent shall write test cases with IDs, steps, expected results, priority and a link to the requirement (Markdown + CSV).MUST
FR-04If no BRD is given, the agent shall derive requirements from the site and label them as inferred.SHOULD
FR-05The agent shall write a test plan (scope, device matrix, order, thresholds, time estimate, assumptions, open questions).MUST
FR-06The agent shall stop after planning and run nothing until a person approves the plan.MUST
FR-07The agent shall run tests on LambdaTest real devices / browser grid, with smoke testing first as a gate.MUST
FR-08The agent shall retry a failed test once and mark tests that pass on retry as Flaky.SHOULD
FR-09The agent shall use a fallback device list when a device is unavailable, and report any substitution.SHOULD
FR-10The agent shall compare the live UI with Figma frames or design images when provided.SHOULD
FR-11The agent shall collect evidence: screenshots, videos, console/network logs and LambdaTest session links.MUST
FR-12The report shall include a Go / No-Go decision, results matrix, defects ranked by severity and requirement traceability.MUST
FR-13The report shall be available as Markdown and Excel; PDF on request.SHOULD
FR-14The agent shall support re-running a saved suite against a previous baseline (regression).COULD

12. Assumptions, constraints and dependencies

  • Dependency: an active LambdaTest / TestMu AI account with real-device access.
  • Dependency: Claude Code with the lambdatest-qa plugin installed; Node.js and Playwright / Selenium on the tester's machine.
  • Constraint: device availability on LambdaTest varies by region and time; some devices may need a fallback.
  • Constraint: sites behind a VPN or firewall need a LambdaTest tunnel.
  • Assumption: a person reviews every plan and report; the AI does not make the release decision alone.
